# 我做了一个公众号排版插件：写 Markdown，一键换主题

写公众号最烦的不是写，而是排版。

尤其当你已经有一篇 Markdown，想在公众号里换一种视觉风格时，流程通常是这样的：先把 Markdown 粘到排版工具，选主题，复制，再粘到公众号后台。过了一会儿觉得另一个主题更好看，又要回去重新复制一遍。

如果正文里还有代码块、表格、引用、多图和嵌套列表，这个过程就更容易出错。

所以这几天我做了一个小工具：**WeChat Theme Switcher**。

它是一个 Chrome / Edge 扩展，直接装在微信公众号编辑页里。你可以把 Markdown 交给它，然后在工作台里一键切换主题，正文会直接在公众号编辑器里更新。

项目地址：

[https://github.com/powcai001/wechat-theme-switcher](https://github.com/powcai001/wechat-theme-switcher)

## 一、它能做什么

现在这个版本的核心流程是：

```text
导入 Markdown
→ 自动写入公众号正文
→ 第一个一级标题写入公众号标题
→ 选择主题
→ 一键切换排版
→ 用公众号自己的按钮保存草稿
```

它不是一个云服务，也不会替你发布文章。它只是把你最重复的排版工作搬进公众号编辑页。

## 二、Markdown 是唯一源文

这个插件最重要的设计决定是：

> Markdown 是源文，公众号正文只是渲染结果。

每次切换主题时，它不会在公众号现有 HTML 上继续打补丁，而是回到 Markdown 重新生成一份干净 HTML，再应用主题。

这样可以避免一个常见问题：你在几个主题之间切换几次以后，旧主题的行内样式、空节点、class、奇怪嵌套和编辑器残留结构叠加在一起，最后文章越来越难看。

在插件里，切换主题永远是重建：

```text
Markdown
→ markdown-it
→ 干净 HTML
→ 主题样式
→ 公众号正文
```

这也意味着，如果你觉得某个主题不合适，只要换下一个，上一次的格式不会污染下一次。

## 三、右侧工作台，而不是来回复制

插件入口在浏览器右侧边缘，垂直居中，点开后是一个排版工作台。

里面可以：

- 导入 `.md` 文件
- 拖拽 Markdown 文件
- 直接编辑 Markdown
- 从公众号正文导入
- 自动同步正文
- 搜索主题
- 查看最近使用
- 收藏常用主题
- 连续切换主题

面板宽度比早期版本大很多，Markdown 编辑区和主题预览都更舒服。

## 四、标题自动同步

公众号文章有单独的标题输入框，正文又有自己的编辑区。以前即使正文里有标题，也常常要手动复制一次。

现在插件会做两件事：

1. 找到 Markdown 里的第一个一级标题；
2. 把它写入公众号标题输入框。

同时，这个标题会从正文中移除，避免读者看到两次标题。

比如 Markdown 是：

```markdown
# Day 13｜长任务一启动，主 Agent 不该跟着失联

正文开始。
```

公众号标题会自动变成：

```text
Day 13｜长任务一启动，主 Agent 不该跟着失联
```

正文则直接从“正文开始”后面的内容开始。

## 五、代码块是重点优化对象

我一开始低估了代码块在公众号里的复杂度。

很多排版工具看起来代码块正常，但粘到公众号后换行丢失，代码被挤成一行。这个插件现在做了两层处理：

1. 代码块仍然输出为公众号兼容的 `pre + code`；
2. 每一行代码内部写入显式 `<br>`，避免编辑器把纯文本换行规范化。

所以像这样的代码：

```python
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

切换多个主题后，缩进、空行和换行仍然会保留。

## 六、其他 Markdown 兼容处理

除了普通标题、段落、粗体、斜体、链接、引用和列表，插件还补了一些实际写作里容易遇到的场景。

### 任务列表

```markdown
- [x] 完成需求分析
- [ ] 检查渲染
```

会渲染成复选框样式。

### 多图布局

连续多张图片不会简单纵向堆叠，会转换成公众号兼容的表格布局。

### 表格

异常的多列表头会尽量修复，例如把挤在第一个单元格里的四个表头拆回四列。

### 引用和深色模式

引用块会做公众号深色模式适配，避免某些背景色在夜间模式下不可读。

### 非白色主题容器

像金融时报这类带背景色的主题，会使用公众号更稳定的 `section` 容器包裹正文。

## 七、隐私边界

这个插件的原则很简单：

> 文章留在你的浏览器里。

它不上传文章，不请求 AI API，不做统计埋点，也不保存你的公众号登录凭证。

Markdown 源文、最近使用主题和收藏主题只保存在浏览器本地扩展存储里。扩展也只在公众号文章编辑路径注入，不在公众号首页和草稿列表页运行。

当然，发布按钮仍然由你自己点。它不会替你群发。

## 八、现在的限制

这是一个开发者预览版，我不想把它说得完美。

目前仍有几件事要注意：

- 微信编辑器 DOM 没有公开契约，页面改版可能导致插件需要更新；
- 标题输入框识别还需要更多真实页面反馈；
- LaTeX 数学公式暂按普通文本处理；
- 图片上传仍使用公众号编辑器自身能力；
- 真实公众号草稿的保存、撤销、重做还需要继续回归。

所以我把它先放在 GitHub 上，作为持续迭代的项目。

## 十、为什么值得做成插件

我想要的工作流其实很简单：

```text
写 Markdown
选主题
保存草稿
预览
发布
```

中间那些来回复制、格式丢失、主题残留和重复手动排版，本不应该消耗创作者太多时间。

这个插件不会替代写作，也不会替代公众号后台。它只负责把“Markdown 到可发布排版”这一段变短。

如果你也经常写公众号，欢迎试试，也欢迎把渲染问题反馈到 GitHub Issues。你的测试文章越复杂，这个插件就会变得越可靠。
